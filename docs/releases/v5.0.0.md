输入标的，输出以双均线为主线的完整股票日线报告：先说明趋势、开仓形态、止损止盈与仓位条件，再用周线、日线、4小时、1小时及斐波那契核对位置、分歧和数据限制。持有周期仍为数周至数月。

本版本将原来的 `technical-trend-v2` 交易规则替换为 `bige-dual-ma-v1`，因此使用主版本号v5。CLI名称及已有研究记录保留。

## 来源与实现边界

思路来源于YouTube「**以太坊教授幣哥**」的公开教学：

- [双均线交易系统](https://www.youtube.com/watch?v=vdCdg4MdwBs)：MA/EMA20、60、120；密集、突破、首次20带回踩，以及对应止损和退出方式。
- [起涨点与回撤](https://www.youtube.com/watch?v=kH7GOeas17A&t=41s)：明确上涨段，结合斐波那契、历史水平区域和均线解释位置。
- [多周期观察](https://www.youtube.com/watch?v=h1wIpEPXx-A&t=534s)：区分不同周期的修复与趋势状态。

本仓库为独立、非官方实现，不代表原作者参与、授权或背书。来源核对使用原站说明、章节和转写稿，未逐帧核验全部示例。1%密集带宽、3根密集、2根突破确认、0.1%止损缓冲、0.5R开盘跳空限制等是项目明确制定的工程参数，不是原作者公布的精确量化规则。

## 交易主线

- 需要至少120根完整日K，使用全部六条MA/EMA20、60、120；历史不足时保持未知。
- 仅合格密集区突破，或已确认突破后的首次20带回踩，能够生成开仓候选。首次触碰失败后不把后续触碰重新认作第一次。
- 止损对应原开仓依据：密集区止损保留原边界；回踩20带的保护位只收紧。
- 预先选定固定R、历史密集区或显式斐波那契扩展目标，缺少目标或剩余盈亏比不足时暂停新仓。
- 使用下一开盘实际价格复核形态与风险；保留手续费、滑点、跳空、同根止损止盈的保守成交顺序及未平仓市值。
- 股票仅做多头/现金，空头形态用于防守观察。未知账户不视为空仓，条件预算不视为真实成交。

## 完整报告与交叉验证

- 交易计划放在报告前面；新增只读 `verification` 字段，版本 `dual-ma-verification-v1`，保存到JSON和journal，audit记录版本与状态。
- 周线、日线、4小时和1小时复用六均线计算，区分支持、方向相反、周期阶段不同、方向未明以及数据不足。
- 自动大波段锚点为可见周线样本最高点及其之前最低点，明确标为研究候选。核对端点先后、段内极值与后续观察，不声称自动选点等于原作者选择。
- 分开计算上涨回吐 `(H−P)/(H−L)` 与价格跌幅 `(H−P)/H`；原起点跌破、跌破后收回、新高越过旧锚点均明确标记。
- 展示回撤位附近的均线带和已确认水平区。回撤不替代开仓形态，不投票修改动作、止损、目标或风险预算。
- 原有33项技术指标及文字形态保留为独立附录，不评分、不绘图，不据此推断机构身份或未来胜率。

## 数据处理

- 检查完整小时K线，按交易所当地开盘聚合4小时窗口，尾盘可较短，不跨夜。
- 韩股小时尾盘缺失时明确标记不完整，不补造4小时确认；未知小时来源及尚未核验的A股午休格线不强行比较。
- 移除同周重复报价；将Yahoo日线UTC时间转换到交易所当地日期。
- 复权口径不同、未知，或同日周线/日线收盘不一致时，停止相应跨周期价位叠加。
- 周线或小时数据失败时保留日线主报告。完整半日市/节假日日历仍未接入，历史缺口会影响均线，报告会披露。

## 使用与迁移

```bash
python naked_k_analysis.py 1810.HK
python naked_k_analysis.py 0700.HK 1810.HK RKLB --json
python naked_k_analysis.py 0700.HK --config-path config.example.json --news
python -m unittest discover -v
```

- 不再采用55根短历史替代、EMA50退出或前20日突破开仓。EMA50/200、ADX、ATR、量价和结构观察不进入新的交易决策链。
- 报告/JSON/journal/audit规则版本改为 `bige-dual-ma-v1`；回测输出schema为 `2.0`。不要跨版本拼接为同一策略业绩。
- 配置新增 `strategy`；旧的 `risk`/`portfolio` 配置仍能读取，但自动采用新策略默认值。已有持仓可补充 `entry_setup` 和 `target_price`，不使用当前新信号补造过去成交依据。
- `breakout` 改指密集区事件；`exit_signal` 不再是通用卖出信号。消费JSON的程序应根据原入场方式、保护价和目标管理退出。
- 原有报告和日志保留。自动回撤候选与配置中的显式高点→后续低点扩展退出相互独立。
