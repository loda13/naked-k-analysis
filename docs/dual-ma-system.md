规则版本：`bige-dual-ma-v1`。2026-10-17 用户指定以该体系作为唯一交易主线，并确认继续研究股票日线、数周至数月持有。CLI 名称保持 `naked_k_analysis.py`。本文件取代旧 v2 设计中的开平仓规则，数据与账户安全约束继续有效。

## 多周期与斐波那契回撤的解释口径

2026-10-17 用户追加起涨点、周线/日线/4小时/1小时及支撑压力要求。另核对作者两段原站转写稿：

- [2025-06-19 XRP，00:41起](https://www.youtube.com/watch?v=kH7GOeas17A&t=41s)：上涨段最低点到最高点画回撤；00:49讨论0.382、0.5、0.618；01:05起看历史水平区域，02:17起结合周线60/120均线，03:05转入日线。
- [2026-02-06 BTC，01:37起](https://www.youtube.com/watch?v=h1wIpEPXx-A&t=97s)：大波段低高点；05:54转日线，结合历史密集区与回撤位；06:34起区分支撑处震荡和可做多条件；08:54提及有经验者切换1小时/4小时。没有从视频中推导出固定的跨周期投票算法。

本项目保留用户选定的股票日线持仓周期。双均线趋势、密集、突破或首次回踩及对应退出始终是报告主线；周线、4小时/1小时和斐波那契用于交叉验证，明确披露支持证据、周期冲突及无法确认之处。回撤价为 `H−r×(H−L)`，r的主观察档为0.382、0.5、0.618、0.786，另展示0.236作补充。回撤位与双均线、此前真实形成的水平区域重合时，解释其共同依据，不把重合计数转换成胜率或直接买入条件。

必须保留原上涨段以检查失效，不为维持原判断而持续把起涨点移到最新低点。最新低点尚无后续上涨，或新高尚未得到后续K线观察时，明确标为待确认；这些端点的研究选择与任何确认根数都属于工程判断。小周期反弹不能自动证明日线反转；价格跌回起涨点下方后，该上涨段的回撤位不能继续解释为已经守住的支撑。

回撤与突破历史高点后的扩展是两组不同锚点：前者L→H定位当前回调，后者前高→随后低点计算1.618等扩展目标，后者的执行约束见下文。已有持仓的止损仍对应原入场依据，不因下方出现新回撤参照而下移止损。

CLI现在默认生成 `dual-ma-verification-v1`，放在交易计划之后：

- 复用同一六均线计算，比较各周期价格位置，输出支持、冲突或处于不同阶段；同方向并不表示收益已验证。各周期还显示最近240根内、两根后续K线确认的局部低点，不能自动把它当作新起涨点。
- 自动大波段候选为可见5年周线样本最高点及此前最低点。检查先低后高、段内极值及端点观察；端点处于样本边界或缺少两根后续周K时标待确认。该算法不保证选中研究者或作者所指的上一轮上涨，人工报告须复核，不能事后选最有利波段却不披露。日期是周结束标签。
- 区分 `(H−P)/(H−L)` 的上涨回吐与 `(H−P)/H` 的价格跌幅。原起点失守、曾跌破后收回或价格越过原高点时分别标记，不夹取到0–1范围、不下移锚点掩盖失效。若最低点与最高点先后无法由周K确定，则不给有效回撤图。
- 与回撤价距离不超过1%的均线带或已确认历史水平区显示为邻近参照。这只是展示容差，端点两根观察也是工程定义，都不是作者的精确阈值。回撤候选不进入回测和开仓、退出、仓位计算；它与策略配置中的新高扩展退出相互独立。
- 数据检查包括同日周/日收盘一致性、复权可比性、完整小时及分组、历史极值与公式。程序检查不是独立第二行情源核验，更不证明经济有效性；人工分析仍需核对行情与波段含义。

跨周期比较披露复权口径、K线标签、数据源与聚合方式。股票4小时从当地开盘按4个钟点小时分组、尾盘可较短，不跨夜；未接入完整半日市日历，不完整窗口剔除并披露。Yahoo/YFinance小时格线已按起始时间处理；其他小时源或A股午休格线未核验时标未知。最新完整交易日缺尾盘或中间小时，1小时标不完整，4小时不给完整序列结论，不拿日线收盘或零成交报价补造K线。各周期复权未知或不同、同日周/日收盘不一致时不叠加价格位置。研究快照继续保存于 `reports/`，下面的日线交易决策链不变。

## 唯一决策链

`已收盘日K → 六均线 → 密集/发散 → 两种形态 → 对应止损与预定目标 → 实际开盘校验 → 账户和组合风险上限`

`naked_k_trend.analyze_trend` 是计划与回测的共同信号入口；`evaluate_entry` 负责下一有效交易日开盘价格检查；`protective_stop` 负责原有持仓的止损类型。周线、EMA50/200、ADX、ATR、Donchian、成交量、结构拐点、33项观察及新闻均不影响此链的候选信号。

### 六线与样本

- MA 是收盘简单平均；EMA 使用前N根收盘均值初始化，此后 `EMA += 2/(N+1) × (Close-EMA)`。与不同平台或不同历史起点可能有初始化差异。
- 不足120根完整日K时方向为未知，不以MA20/60替代MA120。达到120根只表示六线可计算，未必已有完整形态；默认最早形成密集并确认突破还需额外K线。
- 价格在全部六线上方为 `up`，在全部六线下方为 `down`，其余 `transition`。方向本身不产生交易。
- 每个周期的 MA/EMA 组成一个价格带。向上发散要求20带下沿 > 60带上沿，且60带下沿 > 120带上沿；向下相反，不要求同周期MA与EMA内部排序。

### 密集和突破

1. 六线带宽为 `(最高线/最低线-1)×100%`。默认带宽≤1%，连续至少3根完整日K识别一个密集段。
2. 等待突破期间，只在收盘仍处于原密集边界内且当前仍密集时更新边界，取该根六线的最低/最高值。突破开始后冻结此前边界，不把突破K线纳入边界。
3. 默认连续2根收盘在冻结上沿之上确认多头突破；下沿之下确认空头形态。多头候选的确认收盘还须高于当前全部六线，避免大幅冲高后回落到快线下方仍被判成可买入。同一密集段只产生一次突破确认，不要求先有20/60/120多头排列，不叠加前20日新高过滤。
4. 待确认期间回到带内会清除连续计数；切换到另一侧重新计数。未确认的密集区距离最后边界更新超过20根时过期。
5. 只有“非密集→新的连续密集段”达到门槛才开始新一轮。密集并非每日重复建仓；已确认形态只在确认当日产生信号。

### 首次回踩20均线

- 必须先有已确认的密集区突破。向上突破后先出现整根K线低点高于20带上沿，才视为价格已离开20带。
- 随后第一次 `Low <= 20带上沿` 即消耗首次触碰机会，不能在失败后把第二次回踩改称第一次。
- 该次触碰的收盘必须回到20带上沿之上，且当日20、60、120三个带保持向上排列，才确认多头回踩形态。允许影线进入带内，以收盘判断是否守住；这是明确的工程口径。
- 跌回原密集区下方或距突破超过20根后，取消该轮回踩机会。空头观察按镜像计算，但股票多头/现金模式不创建空头仓位。

### 止损、目标与实际开盘

| 开仓方式 | 初始保护价 | 后续保护价 |
| --- | --- | --- |
| 密集区突破 | 冻结密集区下沿 × (1−0.1%) | 保留该次原始价，不跟随其他新形态改变 |
| 首次回踩20带 | 当日20带下沿 × (1−0.1%) | 每个完整收盘后按20带计算，只允许收紧，从下一根生效 |

0.1%缓冲及盘中触价退出是工程执行约定；原片的“有效跌破”没有唯一数值定义。已有持仓的保护位若已高于收盘，安排下一开盘退出，不能把昨日盘中当成已成交。

三种目标通过 `strategy.exit_method` 选择，每次新交易只选一种：

- `fixed_r`（默认）：`目标 = 实际入场价 + take_profit_r × (实际入场价−初始止损)`，默认3R，可设5R等。收盘报告显示参考价，实际开盘含滑点后重算并固定目标。
- `previous_cluster`：只查询当前密集段以前已识别的密集段；选择位于入场参考价上方、价格最近的历史密集区下沿。目标在信号时固定，实际开盘重新检查空间，不因向上跳空临时改选更远目标。没有可用区间则不产生新仓。
- `fibonacci`：必须在 `fibonacci_anchors` 中按ticker显式指定过去的 `high_date` 与随后 `low_date`；从输入日K读取两日的 High/Low。高点必须是当时输入历史的最高点，低点须低于它，当前收盘须已越过高点。目标为 `低点 + ratio × (高点−低点)`，ratio支持1.618、2.618、3.618、4.236。锚点尚未出现、不在可见输入中或无效时暂停新仓，不自动挑选事后最优锚点。有限输入历史不能证明全历史新高；回测须披露人工锚点可能有事后选择偏差。

默认要求预定目标至少3R。多目标分批平仓、滚仓、加仓和杠杆不在这一版股票实现中；每笔交易在选定目标全量退出。固定3R的目标只是预先约定的退出位置，不能证明该空间可达到。

候选仅对紧接信号后的下一有效交易日开盘有效。实际开盘必须仍在入场依据的上沿之上且高于止损；最高入场价为 `信号收盘 + 0.5×信号风险距离`。0.5R是工程跳空限制。回测分别校验市场开盘价和加上不利滑点的成交价，滑点不能把已经失效的形态变成可买入。固定R目标按成交价重算；其他两种目标冻结，若剩余空间不足最低R则拒绝入场。

## 资金与已有持仓

风险预算对应的理论数量为 `可承受亏损金额 / (入场价−止损价)`，再受原有单标的、市场、方向、总仓位和总账户风险上限约束。日线股票继续采用多头/现金、无杠杆，不移植视频的合约杠杆案例。手续费、滑点和跳空可使实际损失大于该理论预算。

账户未知时只提供条件预算，不能认定用户空仓、零回撤或具备执行许可。账户日期不匹配或触发风险上限时暂停新仓。持仓快照可补充 `entry_setup`（`cluster_breakout` / `first_pullback_20`）与 `target_price`。缺少原开仓依据时只保留已提供的原止损/目标，不把今天的新信号当成历史成交依据；原止损也缺失则显示未知。

## 回测约束与输出迁移

- 下一开盘执行，手续费/滑点显式输入。开盘跳过止损按更差开盘成交；开盘已越过目标则按开盘触发并扣不利滑点。日内先后未知且同根触及两价时按止损先行，开仓当天同样适用。
- 目标开仓后固定；保护位只用已收盘数据更新。多日持仓不重复开仓，期末未平仓按市值记录，不虚构终止清仓。
- 生产预热最低120根，首次执行至少需要121根输入。EMA50/200只保留为单独比较策略；起点不足EMA200时明确不可计算，不把空仓曲线当成有效对照。
- JSON/journal/audit 规则版本变为 `bige-dual-ma-v1`；回测容器schema为 `2.0`。旧日志只追加不改写；不同规则不能拼接成同一策略业绩。
- `trend.setup`、`setup_state`、`cluster`、`historical_clusters`、`exit_plan`、`strategy.parameters` 提供审计依据。`breakout` 现在仅表示密集区突破事件；兼容字段 `exit_signal` 恒为false，退出取决于持仓的原始保护价/目标，不应继续用旧EMA50退出逻辑解析它。
- 经济有效性仍为 **UNVALIDATED**。离线测试与实跑报告验证实现和数据链路，不是跨市场成本后样本外收益验证。

## 配置示例

完整默认值见 `config.example.json`。使用固定5R：

```json
{"strategy": {"exit_method": "fixed_r", "take_profit_r": 5, "min_reward_risk": 3}}
```

历史密集区退出：`{"strategy": {"exit_method": "previous_cluster"}}`。

斐波那契配置结构如下，日期和ticker仅演示字段，必须替换成输入历史中的明确锚点：

```json
{
  "strategy": {
    "exit_method": "fibonacci",
    "fibonacci_ratio": 1.618,
    "fibonacci_anchors": {
      "EXAMPLE": {"high_date": "2025-01-10", "low_date": "2025-03-10"}
    }
  }
}
```
